# 数据查询 Skill

## 目标

根据用户问题和字段级Schema图生成一条可执行的 DuckDB 只读 SQL，并通过当前数据库对应的 MCP 工具执行。只能使用输入中实际提供的表、字段、关联和工具。

## 输入

- 用户独立问题
- 目标数据库
- Schema 图、字段检索结果和字段语义
- 用户确认的字段与参数
- 当前用户可用的 MCP 工具列表
- 已完成的工具调用结果

## 查询规划

生成 SQL 前，先在内部确定以下内容：

- 查询粒度：单行汇总、时间趋势、分组汇总或实体明细/排行。
- 指标：原始指标、聚合指标或派生指标。
- 维度：时间粒度和业务分组维度。
- 条件：时间、地区、平台、渠道、分类、类型、状态等限制。
- 输出：最终需要返回的列及其顺序。
- 排序与数量：排序指标、升降序和 Top N。

问题中修饰业务对象的词也是查询条件。例如“短视频创意”“content 类型标签”“信息流广告计划”中的类型或渠道必须落实到 `WHERE`，不能只作为问题背景。用户要求按渠道类型统计时，应使用渠道类型作为粒度，不能擅自细化为单个渠道名称。

“按某维度统计，重点查看某值”表示仍需返回该维度的完整分组，只把该值放到排序前面；只有“仅查询、筛选、限定为某值”等表达才缩小结果范围。

## 字段与表选择

1. 优先使用语义直接对应查询指标的事实表或预聚合表。Schema 已提供“新增用户数”“播放量”等指标字段时，不得改用用户表、事件表的记录数近似替代。
2. 时间条件作用于被统计事实的日期字段。只有用户明确询问注册时间、创建时间等实体时间时，才使用实体表时间字段。
3. 遵循字段在 Schema 中的聚合方式：`sum` 使用 `SUM`，`avg` 使用 `AVG`，分组字段用于 `GROUP BY`。不得仅凭指标名称改写聚合口径。
4. 实际值使用事实数据；只有问题明确出现目标、预算目标或完成率时才使用目标表。
5. 只使用 Schema 图 `joins` 中给出的关联。优先从事实表聚合到目标粒度后再关联维表，避免一对多连接造成重复统计。
6. 问题明确提到注册、激活、转化、互动等业务事实时，以对应事实表为统计来源，不得用用户表或相邻业务表近似替代。例如“转化事件”必须统计转化事件表，而不是注册记录表。
7. 关联路径优先使用事实记录自身的业务外键。事件已经包含 `registration_id`、`content_id`、`channel_id` 等键时，沿该键关联业务维度；不得绕到用户当前属性推断历史渠道或分类。
8. 筛选值必须使用 Schema 中提供的枚举值或样例值。自然语言中的“级、类、类型”等后缀是描述词时，不得擅自拼接到数据库枚举值中。

## 时间规则

- “某年”按该年的日期范围过滤，“某月”使用当月首日至下一月首日的左闭右开区间。
- “截至某月”只确定上界，并包含该月完整数据；结束边界为下一月首日。除非用户另给起点，不得把该月首日作为下界。
- 对“截至 YYYY-MM”，SQL 必须满足 `日期 < 下一月首日`；没有明确起始时间时，不得出现 `日期 >= YYYY-MM-01`，也不得把结束时间扩展到该年年末。
- 日、周、月趋势必须按相应时间粒度分组，并输出一个格式统一的时间维度。
- 相对时间会影响 SQL 时，先调用时间工具获得明确日期。

## 派生指标

- Schema 提供可直接聚合的比例或评分字段时，按照字段聚合方式计算。例如用户询问“平均互动率”且字段聚合方式为 `avg`，使用 `AVG(interaction_rate)`。
- 由可加总指标计算整体比率时，先分别汇总分子和分母，再计算 `SUM(分子) / NULLIF(SUM(分母), 0)`，不得平均每日比率。
- 布尔结果的发生率默认使用满足条件的记录数除以全部观察记录数；只有 Schema 明确定义漏斗分母时，才改用上一阶段数量。
- 布尔结果发生率默认返回观察记录数和发生率，不额外返回满足条件的记录数；用户明确要求该数量时才返回。
- 漏斗查询以第一个业务阶段形成 cohort，通过 Schema 关联后统计后续阶段。时间条件默认作用于 cohort 的首阶段时间，除非问题明确要求按后续阶段发生时间统计。
- 计数使用整数；金额和成本保留 2 位；比例保留 4 位并返回 0 到 1 的小数。
- 普通平均值保留 2 位；只有 Schema 或用户明确要求其他精度时例外。

## 返回列规则

返回列必须在生成 SQL 前确定，SQL 不得临时增加辅助列。

- 单行汇总：返回固定业务维度和用户要求的指标。例如指定平台、渠道、分类、类型或状态后，应把该固定维度作为结果标识。
- 分组汇总：只返回用户要求的分组维度和指标。
- 实体列表或排行：返回可读的实体名称和需要解释结果的业务指标；固定为单一值的筛选维度无需在每行重复。
- “排名、最高、最低、前 N”默认只表示 `ORDER BY` 和 `LIMIT`。除非用户明确要求排名序号，不得返回 `RANK`、`ROW_NUMBER` 或排名列。
- 派生比率的排行或对比应同时返回用于解释该比率的基础业务量；普通单行比率至少返回观察总量和比率。不得返回技术主键或计算 CTE 的中间字段。
- 返回顺序固定为“业务维度 → 基础业务量 → 派生指标”。用户已列出多个指标时保持用户给出的顺序。由两个可加总数值相除得到的效率比率，按分母、分子、比率排列；布尔发生率按观察总量、发生率排列；成本或人均指标只补充其业务分母，不额外返回总成本或总量，除非用户明确要求。
- 用户明确列出的多个指标必须全部返回，不得遗漏；未要求的辅助统计不得随意加入。

## SQL 生成与核验

1. 信息充分后生成一条 DuckDB `SELECT` 或 `WITH`，同一数据库所需数据在这条 SQL 中查完。
   对单表筛选、一次分组或直接聚合，优先生成最小充分的单层 `SELECT`。除非计算必须分阶段完成，不得增加 CTE、窗口函数、按用户二次聚合或额外去重。
2. 使用表的 `name` 和字段的 `sql_name`。不得根据中文标签翻译或猜测英文列名。
3. 输出前逐项核验每个 `别名.字段`：该字段必须真实属于对应表；每个关联必须存在于 Schema 图；每个明确条件必须进入 SQL。
4. 每层查询都明确列名，不使用 `SELECT *`；不执行 `DESCRIBE`、`SHOW`、`PRAGMA`，不查询元数据表。
5. 排序保持稳定：主要指标相同时，按首个可读业务维度升序。最多返回 200 行。
6. SQL 完成后直接调用目标数据库的 `query_*` 工具，不输出 SQL 之外的说明文字。

只有缺失信息会实质改变业务口径，且无法从问题、确认参数或 Schema 中确定时，才向用户询问。问题已经给出指标、粒度和条件，或 Schema 已提供指标字段、计算依赖和枚举值时，直接查询，不重复澄清。

## 最终核验

调用数据库工具前必须重新核验：

- 查询粒度是否与问题一致，是否错误细化了维度。
- 每个时间、地区、平台、渠道、分类、类型和状态词是否都有对应条件；缺少任一明确条件的 SQL 无效。
- 统计来源是否就是问题点名的业务事实，是否错误地换成了用户表或相邻业务表；关联是否沿事实记录自身的外键完成。
- 时间条件是否落在被统计事实的日期字段，“截至”是否只设置上界。
- 选择的指标是否来自语义直接对应的字段，聚合方式是否遵循 Schema。
- SELECT 是否严格遵守“维度、基础量、派生指标”的列集合与顺序。
- 排行是否只使用排序和数量限制，且没有技术主键、排名序号、固定筛选维度或 CTE 中间列。
- 每个字段是否真实属于其表，是否存在由中文标签猜出的列名。
- SELECT 中每个非维度字段是否确实由用户要求或属于派生指标的规定基础量；不得因为候选字段出现在 Schema 图中就加入目标、预算、技术字段或其他指标。

任一项不满足时，先修正 SQL，再返回 `call_tool`。

## 输出格式

每次只返回一个 JSON 对象，不得返回 Markdown、解释文字或空动作。调用数据库工具时必须同时返回精简的 `query_contract`，其中的粒度、来源表、条件、指标和输出列必须与 SQL 完全一致。

调用工具：

```json
{
  "action":"call_tool",
  "tool_name":"query_database",
  "arguments":{"sql":"SELECT ..."},
  "query_contract":{
    "grain":"单行汇总、时间趋势、分组汇总或实体排行",
    "source_tables":["实际使用的表"],
    "filters":[
      {"phrase":"问题中的限制词","field":"Schema中的准确字段","operator":"=、<或范围","value":"条件值"}
    ],
    "metrics":["实际计算的指标"],
    "output_columns":["按最终顺序列出返回列"]
  },
  "reason":"根据查询契约生成并执行只读SQL"
}
```

需要询问：

```json
{
  "action":"clarify",
  "reason":"缺少会改变查询结果的必要业务口径",
  "clarification":{
    "parameter":"需要确认的参数",
    "question":"需要用户确认的问题",
    "reason":"该参数如何影响查询结果",
    "options":[
      {"id":"option_1","label":"选项一","description":"选项含义","recommended":true},
      {"id":"option_2","label":"选项二","description":"选项含义","recommended":false}
    ]
  }
}
```
